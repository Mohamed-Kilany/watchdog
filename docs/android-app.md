# Android app — permissions and exported surface

The remote app (`android/`, package `app.watchdog.remote`) is installed and driven
entirely by the host; the only user action is the OS USB-debugging authorization
prompt. This document is the normative list of permissions and of every component
that is visible outside the app.

## Permissions

Declared in `android/app/src/main/AndroidManifest.xml`. No broad storage permission
is requested: captures live in app-specific storage (`files/media/`) and the host
pulls them through the ADB sync protocol, which runs as the `shell` user and needs
no app permission.

| Permission | API | Why | Granted by |
|---|---|---|---|
| `CAMERA` | all | Camera2 preview and JPEG frames for the live feed. | runtime `pm grant`, appops `CAMERA` |
| `RECORD_AUDIO` | all | Audio track in recordings (M5). Declared now so the foreground-service type is stable. | runtime `pm grant`, appops `RECORD_AUDIO` |
| `FOREGROUND_SERVICE` | 28+ | Keep capture alive when the activity is gone / screen is off. | normal (install-time) |
| `FOREGROUND_SERVICE_CAMERA` | 34+ | Required for a `camera` typed foreground service. | normal (install-time) |
| `FOREGROUND_SERVICE_MICROPHONE` | 34+ | Required when the service adds the `microphone` type (recordings with audio). | normal (install-time) |
| `POST_NOTIFICATIONS` | 33+ | Show the mandatory foreground-service notification. | runtime `pm grant` |
| `WAKE_LOCK` | all | Partial wake lock while streaming with the screen off; released when idle. | normal (install-time) |
| `INTERNET` | all | LAN/TCP transport; the abstract local socket itself is not network I/O. | normal (install-time) |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 23+ | Fallback: let the app show the system exemption dialog if `dumpsys deviceidle whitelist` cannot be used. | normal (install-time) + user action |

`uses-feature android.hardware.camera.any` is required: the app has no purpose on a
device without a camera.

### Grant commands used by provisioning (M3-T13)

```sh
adb shell pm grant app.watchdog.remote android.permission.CAMERA
adb shell pm grant app.watchdog.remote android.permission.RECORD_AUDIO
adb shell pm grant app.watchdog.remote android.permission.POST_NOTIFICATIONS

# AppOps cover the same capabilities plus background execution. Granting both
# makes the flow robust on OEM builds that reset runtime grants.
adb shell cmd appops set app.watchdog.remote CAMERA allow
adb shell cmd appops set app.watchdog.remote RECORD_AUDIO allow
adb shell cmd appops set app.watchdog.remote START_FOREGROUND allow
adb shell cmd appops set app.watchdog.remote RUN_IN_BACKGROUND allow
adb shell cmd appops set app.watchdog.remote RUN_ANY_IN_BACKGROUND allow

# Battery optimization exemption without touching the phone.
adb shell dumpsys deviceidle whitelist +app.watchdog.remote
adb shell cmd appops set app.watchdog.remote REQUEST_INSTALL_PACKAGES deny

# Screen: recorded original values are restored by `watchdog device restore`.
adb shell settings get global stay_on_while_plugged_in
adb shell settings put global stay_on_while_plugged_in 7
```

`pm grant` succeeds only for runtime permissions the manifest declares; normal
permissions are granted at install time. Every command above is idempotent.

## Exported components

Rule: a component is exported only if the host must reach it with `am`/`cmd` before
any in-app session exists. Every exported entry point requires a **per-session
token** in an intent extra and fails closed (logs and stops) when it is missing,
malformed or does not match the active session.

| Component | Exported | Protection |
|---|---|---|
| `MainActivity` | yes (launcher) | none needed: it only shows the on-device UI and starts the service through an internal intent. |
| `CaptureService` (M3-T03) | yes | action `app.watchdog.remote.action.START`; requires `app.watchdog.remote.extra.SESSION_TOKEN` (32 lowercase hex chars, 128 bits). The token is also the token the host must present in `HOST_HELLO`; a mismatch is rejected before the camera opens. |
| `ProvisioningReceiver` (M3-T03) | yes | actions `…action.STOP` / `…action.STATUS`; same token extra, validated before acting. |
| everything else | no | internal only. |

The token is generated by the host once per provisioning session, passed with the
start intent and echoed in `HOST_HELLO.session_token` (`docs/protocol.md` §3). A new
token from a new host session replaces the old one (`session_replaced`).

## Other hardening

- `android:allowBackup="false"` so tokens/logs are never uploaded to cloud backup.
- `android:debuggable` is false in release builds (AGP default).
- R8 is enabled for release (`isMinifyEnabled`, `isShrinkResources`).
- No `android:usesCleartextTraffic` override; the app never talks HTTP.
- Media and logs stay in app-specific storage; there is no `MANAGE_EXTERNAL_STORAGE`
  or `READ/WRITE_EXTERNAL_STORAGE` permission.
