# Camera controls

> Status: descriptor live (M4-T01); state sync and the command pipeline live
> (M4-T02/T03); exposure controls live (M4-T04); focus controls live (M4-T05);
> white balance live (M4-T06); zoom and lens live (M4-T07); flash, scene and
> image processing live (M4-T08); output configuration live (M4-T09).
> The authoritative machine-readable source is the **capability descriptor** published by
> the app at handshake and on demand (`watchdog device capabilities --json`). This page
> documents semantics and device differences; entries are filled in during M4 as each
> control lands, and cross-checked against the control compatibility matrices generated by
> "probe everything" (M4-T10).

## Capability descriptor

Every handshake carries one descriptor per camera id. The app builds it from
`CameraCharacteristics` without opening the camera and lists, per control, either its
available modes or its `min`/`max`/`step` range; unsupported controls are named in
`unsupported` with a reason. Streams, FPS ranges, lens metadata and the full inventories
of request/result/characteristics keys (name + Java type) are included. Schema:
[protocol.md §5.13](protocol.md#513-capability-descriptor-embedded-in-hello_ack--get_capabilities).

`watchdog device capabilities` prints a human summary; `--json` prints the raw map for
issue reports and compatibility matrices. Commands are only valid against controls the
descriptor reports as supported; anything else is an error, never a silent no-op.


## Conventions

- **Auto / manual**: where the hardware allows both, the UI shows a toggle; manual values
  clamp to the reported ranges/steps.
- **Actual vs requested**: requested is what you asked for; actual is what the camera
  reports in `TotalCaptureResult`. They can legitimately differ (step rounding, scene
  overrides when AE is on). UI shows both; state JSON carries `requested`/`actual`/`locked`/
  `supported`/`source`.
- **Locks** (AE / AWB / AF) are first-class buttons with live state badges.
- Unsupported controls are **hidden or disabled and listed as unsupported** — never
  silently ignored.
- Ranges come from `CameraCharacteristics`, never from hardcoded tables.

## Exposure

| Control | Notes |
|---|---|
| AE mode (on/off/on-flash) | `CONTROL_AE_MODE_*`; off = manual ISO/time/frame-duration |
| Exposure time (ns) | `SENSOR_EXPOSURE_TIME`; clamps to `SENSOR_INFO_EXPOSURE_TIME_RANGE` |
| ISO | `SENSOR_SENSITIVITY`; range from `SENSOR_INFO_SENSITIVITY_RANGE` |
| Frame duration (ns) | `SENSOR_FRAME_DURATION`; caps fps |
| Exposure compensation | `CONTROL_AE_EXPOSURE_COMPENSATION` step count; descriptor `min`/`max`/`step` are steps, `ev_step` is the EV each step represents |
| AE lock | `CONTROL_AE_LOCK` (result: `CONTROL_AE_STATE`) |
| AE metering regions | normalized device coords; up to 5 typically |
| AE target FPS range | `CONTROL_AE_TARGET_FPS_RANGE` |
| Anti-banding | `CONTROL_AE_ANTIBANDING_MODE`: off/50Hz/60Hz/auto — **default for filming screens: match mains (50 or 60 Hz)** |
| AE precapture | trigger for metering/AF for still capture |

## Focus

| Control | Notes |
|---|---|
| AF mode | `CONTROL_AF_MODE`: off/auto/macro/continuous-video/continuous-picture/EDOF, only the modes in the descriptor |
| Focus distance | `LENS_FOCUS_DISTANCE` in dioptres (0 = infinity); implies `af_mode = OFF`; range is `0..LENS_INFO_MINIMUM_FOCUS_DISTANCE` |
| AF lock | `af_lock = true` switches to one-shot AF, triggers a scan and remembers the previous mode; unlocking restores it. Live state comes from `af_state` (`focused_locked` / `not_focused_locked`) |
| AF regions | `CONTROL_AF_REGIONS`, normalized `{x,y,w,h,weight}` like AE regions, 1..`max_regions` |
| AF trigger | one-shot `start` / `cancel`; pair with `af_regions` for tap-to-focus |
| AF state | `af_state` readout: inactive / passive_scan / passive_focused / active_scan / focused_locked / not_focused_locked / passive_unfocused |

Tap-to-focus from the host: send `af_regions=[{x,y,w,h}]` plus
`af_trigger=start`; watch `af_state` transition `active_scan → focused_locked`
(or `not_focused_locked` when the scene has too little contrast). Fixed manual
focus (`focus_distance`) is the recommended setting for filming screens; avoid
continuous AF hunting.

## White balance

| Control | Notes |
|---|---|
| AWB mode | `CONTROL_AWB_MODE` presets (off/auto/incandescent/fluorescent/daylight/cloudy/…), only the modes in the descriptor |
| AWB lock | `awb_lock = true` freezes `CONTROL_AWB_LOCK`; `awb_state` reports inactive/searching/converged/locked and `awb_gains` shows the reported RGGB gains |
| AWB regions | `CONTROL_AWB_REGIONS`, normalized `{x,y,w,h,weight}` like AE regions, 1..`max_regions`; meaningful while AWB is running |
| Manual gains | `awb_gains = {r,g_even,g_odd,b}` where `COLOR_CORRECTION_GAINS` is available; implies `awb_mode = OFF`, clears `awb_lock` and sets `COLOR_CORRECTION_MODE = TRANSFORM_MATRIX`. Components use the descriptor's `min`..`max` (0..8 by default) |
| Colour matrix | `color_transform` is a row-major 3×3 matrix of 9 numbers (`COLOR_CORRECTION_TRANSFORM`); same implications as manual gains |
| Colour effects | `effect` and `aberration_correction` are gated by their descriptor mode lists |

A manual colour temperature is built from the two primitives: capture the
converged `awb_gains` while pointing at the screen, then send a `color_transform`
that maps the sensor colour space to the display target. `awb_state` turns
`inactive` when AWB is off, and the `awb_gains` actual stays fixed while the
manual values are requested.

## Zoom and lens

| Control | Notes |
|---|---|
| Zoom ratio | `zoom_ratio` uses `CONTROL_ZOOM_RATIO` when the camera reports `CONTROL_ZOOM_RATIO_RANGE` (API 30+); otherwise the app centres a `SCALER_CROP_REGION`. The descriptor's `min`/`max`/`step` and `legacy_crop_region` say which path is active. `zoom_actual` is read back from the capture result (or derived from the crop width) |
| Optical zoom / focal length | `lens.focal_lengths` lists the lens set in mm; `lens.optical_zoom` gives the span relative to the widest lens (`min` 1.0). Logical multi-camera devices also list `physical_ids` (camera selection is M4-T09) |
| Aperture | `lens.apertures` is fixed lens metadata (`LENS_APERTURE` readout); Camera2 has no request key for a variable aperture |
| Filter density | `filter_density` is settable only when `lens.filter_densities` lists a real choice; its `values` array is the accepted set. Otherwise the control is unsupported and `lens_filter_density` still reports the actual ND density |
| Optical stabilization | `optical_stabilization` from `LENS_INFO_AVAILABLE_OPTICAL_STABILIZATION` (`LENS_OPTICAL_STABILIZATION_MODE`); effective in `CONTROL_MODE = AUTO` with video stabilization off |
| Video stabilization | `video_stabilization` from `CONTROL_AVAILABLE_VIDEO_STABILIZATION_MODES` (`CONTROL_VIDEO_STABILIZATION_MODE`); when both stabilizations are on the platform ignores video stabilization |
| Lens shading | `lens_shading` maps to `SHADING_MODE`; modes come from `SHADING_AVAILABLE_MODES` (off/fast/high quality) |
| Distortion correction | `distortion_correction` maps to `DISTORTION_CORRECTION_MODE` (Android 13 / API 33); modes come from `DISTORTION_CORRECTION_AVAILABLE_MODES`. Devices without it are listed in `unsupported` |

Lens readouts (`TotalCaptureResult`): `lens_focal_length` (mm), `lens_aperture`
(f-number), `lens_filter_density` and `lens_state` (`stationary` / `moving`). The
descriptor's `lens.focus_distance_calibration` tells the host whether the manual
focus distance is calibrated, approximate or uncalibrated.

## Flash / torch / scene / image processing

| Control | Notes |
|---|---|
| Torch | `torch = true/false` maps to `FLASH_MODE_TORCH` / `FLASH_MODE_OFF`; advertised only when `FLASH_INFO_AVAILABLE` |
| Flash mode | `flash_mode` modes (off/single/torch) from the descriptor |
| Scene mode | `scene_mode` from `CONTROL_AVAILABLE_SCENE_MODES` (`CONTROL_SCENE_MODE`) |
| Noise reduction | `noise_reduction` from `NOISE_REDUCTION_AVAILABLE_NOISE_REDUCTION_MODES` |
| Edge enhancement | `edge_enhancement` from `EDGE_AVAILABLE_EDGE_MODES` |
| Hot pixel | `hot_pixel` from `HOT_PIXEL_AVAILABLE_HOT_PIXEL_MODES` |
| Tonemap mode | `tonemap` from `TONEMAP_AVAILABLE_TONE_MAP_MODES` |
| Contrast curve | `tonemap_curve` when the mode list includes `CONTRAST_CURVE`: `{"red":[in,out,…],"green":[…],"blue":[…]}`. Each channel has 2..`max_points` points, inputs strictly increasing, all values in `[0,1]`. Implies `tonemap = CONTRAST_CURVE`; the mode alone sends a neutral linear curve |
| Gamma | `tonemap_gamma` when `GAMMA_VALUE` is available (`0.1..5.0`); implies `tonemap = GAMMA_VALUE` |
| Preset curve | `tonemap_preset_curve` when `PRESET_CURVE` is available: `0` = sRGB, `1` = Rec.709; implies `tonemap = PRESET_CURVE` |
| Lens shading | `lens_shading` (`SHADING_MODE`) |
| Face detection | `face_detect` from `STATISTICS_INFO_AVAILABLE_FACE_DETECT_MODES`; `face_count` and `faces` (`[{id,score,x,y,w,h}]`, normalized to the active array) are readouts |
| Test pattern | `test_pattern` from `SENSOR_AVAILABLE_TEST_PATTERN_MODES` (`SENSOR_TEST_PATTERN_MODE`); a solid-colour pattern uses the device's default pattern data |

Face boxes are data only: the host draws them over the viewfinder (M6-T04) and
they are never burned into the device video or the stream.

## Output configuration

These controls are **structural**: they change the frame pipeline or capture
session instead of a Camera2 request key. The app validates the whole structural
batch first and applies it atomically; an invalid value leaves the previous
configuration untouched. `camera_id` and `physical_camera_id` are resolved
before the other structural controls in a batch, so dependent values validate
against the selected camera's descriptor.

| Control | Notes |
|---|---|
| Camera | `camera_id` values from the descriptor. Switching camera rebuilds the state store and resets every output control to the new camera's defaults |
| Physical camera | `physical_camera_id = "none"` selects the logical camera; any other value must be one of `physical_ids`. Sessions use `OutputConfiguration.setPhysicalCameraId` and requests target that physical camera (API 28+) |
| Stream size | `stream_size = {width,height}` for the YUV_420_888 live stream; only even sizes reported by `SCALER_STREAM_CONFIGURATION_MAP`. Changing it rebuilds the `ImageReader` and capture session |
| JPEG quality | `jpeg_quality` 1..100 (descriptor `min`/`max`), used by the live encoder and still capture |
| Stream rotation | `stream_rotation` 0/90/180/270; carried in the `FRAME` header, pixels are never rotated on the device |
| Still format | `still_format` is `JPEG`, plus `RAW_SENSOR` when the camera advertises RAW; M5 writes DNG for RAW |
| Still size | `still_size = {width,height}` for the current still format. Switching format selects the largest size of the new format when the old size is unavailable |
| Video size | `video_size = {width,height}` from the MediaRecorder/PRIVATE outputs |
| Video bitrate | `video_bitrate` in bits/s, 100 kbit/s..100 Mbit/s |
| Video codec | `video_codec` is `h264` or `h265`, only when a platform encoder exists |
| Video container | `video_container` is `mp4` |
| Audio | `audio = true/false` for recording, advertised only when an AAC encoder exists |

Defaults: 1280x720 live stream, maximum JPEG still, 1920x1080 video, 8 Mbit/s,
H.264 in MP4, audio off, rotation 0.

Validation rules:

- Unsupported, unknown or out-of-range values return `UNSUPPORTED`,
  `UNKNOWN_CAMERA`, `INVALID_VALUE` or `OUT_OF_RANGE`; the whole structural batch
  is rolled back.
- `ae_fps_range` is not structural. When a stream-size change makes the requested
  range impossible, the app selects the best supported range and reports it with
  `source = "auto"`. An explicit impossible FPS/size pair returns
  `UNSUPPORTED_COMBINATION`.
- RAW still capture with a live stream above 1080p is rejected as
  `UNSUPPORTED_COMBINATION`. Other concurrent-surface combinations are validated
  by the capture-session callback when M5 adds them.
- Video and still settings are recorded in the state model now; M5 consumes them
  when still capture and recording land.

## Filming screens — best practice

1. **Anti-banding 50/60 Hz** matching mains — eliminates rolling-scan flicker.
2. Manual exposure (AE off) with ISO pinned low and exposure time near the panel's frame
   period, or a multiple of it — kills beat-frequency flicker.
3. **AWB lock** (and fixed white point) — prevents colour pumping from content changes.
4. Fixed manual focus; avoid continuous AF hunting.
5. Slight moiré is unavoidable at some angles — angle the phone a few degrees instead of
   dead-on when possible.
6. Grid overlay (host-drawn) to align with bezel corners.
