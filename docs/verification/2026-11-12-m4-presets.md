## Apply after a fresh install

Before the apply the freshly provisioned app was in auto mode:
`ae_mode=1`, `iso=60`, `exposure_time_ns=30000000`, `zoom_actual=1`, `awb_lock=false`,
`af_mode=4`, `focus_distance=2.848`, `anti_banding=3`
([controls-fresh.json](2026-11-12-m4-presets/controls-fresh.json)).

`device preset apply "M4 T11 BOM" --json` (the same fixture imported from a UTF-8-BOM file)
returned exit `0`, `round_trip_ms=183`, `error=null`, and **10/10 accepted results** — the
nine stored controls plus the `af_mode=0` implication triggered by `focus_distance`
([apply-fresh.json](2026-11-12-m4-presets/apply-fresh.json)).

## Apply after changing the device

The device was moved to a different state (`ae_mode=1`, `zoom_ratio=1.0`,
`awb_lock=false`, `af_mode=4`, `anti_banding=0`; actuals showed auto ISO 93 and 30 ms
exposure) and the preset applied again. All results were `ok`, exit `0`, round-trip
177 ms, and the state returned to the table above. The same round trip was repeated with
the imported copy (`M4 T11 Imported`, 70 ms) and with the final artifact (210 ms), always
with zero failures.

## Export, import, list, show, delete

- `preset export "M4 T11 Manual" exported-manual.json` wrote the exact schema-v1 JSON shown
  above.
- `preset rm "M4 T11 Manual"` removed it; `preset list` then showed only the default-save
  fixture.
- `preset import exported-manual.json --name "M4 T11 Imported"` stored 9 controls, kept the
  exported `created_at` (`12:15:23.308Z`) and refreshed `updated_at`
  ([preset-list.json](2026-11-12-m4-presets/preset-list.json)).
- `preset show` printed name, description, schema, control count, timestamps and sorted
  control values.
- Importing a BOM-prefixed copy as `M4 T11 BOM` succeeded on the final artifact. The first
  run of this check used a BOM-free copy; the BOM tolerance was added in `61140b4` after the
  initial import attempt exposed the Windows-editor case, and the on-device retest above used
  the final binary.

## Validation

Both bad imports exited `1` with the documented `INVALID_REQUEST` code:

- `{"schema_version":1,"name":"Bad Readonly","controls":{"battery_percent":50}}` →
  `control 'battery_percent' is read-only and cannot be stored in a preset`
- `{"schema_version":2,"name":"Bad Schema","controls":{"iso":100}}` →
  `preset schema_version 2 is not supported (expected 1)`

The store also rejects empty names/control maps, path separators, null values, oversized
names/descriptions/values and one-shot triggers; those are covered by unit tests and were
not repeated on the device.
