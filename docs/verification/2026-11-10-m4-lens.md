### Legacy crop fallback

The A51 reports `CONTROL_ZOOM_RATIO_RANGE`, so the device run exercises the native zoom
path only. The `SCALER_CROP_REGION` fallback is covered by the JVM unit tests in
`ZoomMathTest` (ratio 1/2, odd sensor sizes, offset active arrays, extreme ratios, invalid
input and the inverse read-back), which run in the `android (assembleRelease)` CI job.

## Failures found (do not hide)

| # | Severity | Description | Issue link | Workaround |
|---|---|---|---|---|
| 1 | low | The A51 reports a slightly smaller zoom ratio than requested (4.0 → 3.989, 8.0 → 7.968) because the HAL rounds the zoom crop to whole sensor pixels. The applied value is acknowledged as requested; only the reported `zoom_actual` carries the rounding. | n/a (device behaviour) | device checks compare zoom with a 1 % relative tolerance; the control itself is correct |
| 2 | low | `device set-control` returns an empty `actual` when an assignment does not change the current state, because the state stream only sends deltas. This is correct protocol behaviour but makes no-op assignments look unacknowledged in the CLI payload. | n/a (CLI best-effort read) | read the settled value from a follow-up `watchdog device controls` snapshot |
