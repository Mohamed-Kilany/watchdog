### Camera recovery

After a transient `CAMERA_DISABLED` open failure the app used to log
`ERROR → CLOSED → CLOSED…` while frames flowed, because `CameraDevice.StateCallback.onClosed`
reset the state after `onError` had already moved it to `ERROR`. Recovery then re-opened the
camera while `Opened`/`Configured`/`StreamStarted` were rejected as invalid, so
`applyControls` never replaced the repeating request (controls silently no-oped).

With the fix (PR #12) the state machine only leaves `ERROR`/`RECOVERING` on a successful
transition and the controller only emits `Closed` for a user close. Log for this run:

```
camera 0 opening
camera OPENING (was none)
camera OPEN (was OPENING)
camera CONFIGURED (was OPEN)
camera STREAMING (was CONFIGURED)
```
